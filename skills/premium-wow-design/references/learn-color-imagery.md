# Цвет и арт-дирекшн изображений для премиальных сайтов

Справочник для вёрстки на чистом HTML/CSS: wellness, флористы, отели/рестораны, бьюти, D2C.
Принцип: **фото задаёт палитру, а не наоборот.** Цвет в интерфейсе подыгрывает изображению.

---

## 1. Палитра из фото бренда

1. Возьми 1–3 главных фото (hero, продукт, интерьер). Сними пипеткой 5–8 цветов: самые светлые блики, тени, 2–3 средних тона, 1 акцент (самый насыщенный маленький объект — цветок, губы, керамика).
2. Не бери цвета как есть: фото-пиксели грязные. Переведи в OKLCH и «почисти»: округли hue, задай chroma осознанно.
3. Роли:
   - **Фон (60%)** — самый светлый тон фото, chroma 0.005–0.02 (тёплый офф-вайт, не #fff).
   - **Поверхности/секции (30%)** — средний тон фото или тёмная версия тени (для тёмных секций).
   - **Акцент (10%, реально 2–5% площади)** — один цвет для CTA, ссылок, мелких деталей. Hue из фото, chroma выше остальных.
   - **Текст** — не #000: почти-чёрный с hue фона (oklch 0.2–0.25, chroma 0.01–0.02).
4. Проверка: положи палитру рядом с фото — если фото «выпадает», палитра неверна (обычно акцент слишком насыщен или нейтрали не той температуры).

### 60/30/10 — как применять честно
- Считается по **площади экрана**, включая фото. Если фото занимают 40% экрана, они и есть часть 60/30.
- Премиальность = малая доля акцента. Если CTA, бейджи, иконки, подчёркивания все акцентные — акцент перестаёт работать. Акцент только на 1 главное действие на экране.
- Второй акцент допустим только как вариант первого (светлее/темнее), не новый hue.

### Нейтрали с температурой
- Чистый серый (chroma 0) выглядит дешёво/технично рядом с тёплыми фото. Добавь hue бренда: chroma 0.005–0.015 для фонов, 0.01–0.03 для бордеров и вторичного текста.
- Тёплая шкала (hue 60–85): wellness, бьюти, флористы, хоспиталити. Холодная (hue 220–260): тех, медицина, минеральная косметика.
- Правило Refactoring UI: серые надо «насыщать» в сторону температуры бренда; чем светлее/темнее серый, тем больше насыщенности можно добавить, чтобы он не выглядел мыльным.
- Все нейтрали — из одного hue. Смешение тёплого фона и холодного серого текста видно сразу.

## 2. Тинты/шейды в OKLCH

OKLCH перцептивно равномерен: шаг L = видимый шаг светлоты, hue не «уплывает» (в HSL синий и жёлтый с L=50% имеют разную видимую яркость).

```css
:root{
  --h: 70;                                   /* hue бренда из фото */
  --bg:        oklch(0.975 0.008 var(--h));
  --surface:   oklch(0.945 0.014 var(--h));
  --line:      oklch(0.88  0.02  var(--h));
  --muted:     oklch(0.52  0.025 var(--h));  /* вторичный текст, ≥4.5:1 на --bg */
  --ink:       oklch(0.23  0.018 var(--h));
  --dark:      oklch(0.21  0.02  var(--h));  /* тёмные секции */
  --accent:    oklch(0.55  0.11  35);        /* терракота */
  --accent-hi: oklch(from var(--accent) calc(l + .08) c h);
  --accent-lo: oklch(from var(--accent) calc(l - .08) c h);
}
```
- Шкала 50–950: держи hue и шагай по L (0.97, 0.93, 0.87, 0.78, 0.68, 0.58, 0.48, 0.38, 0.29, 0.21). Chroma максимальна в середине шкалы и падает к краям — иначе крайние тона выходят за sRGB и клипаются.
- Светлые тинты жёлтых/оранжевых можно делать с чуть большей chroma; тёмные шейды синих — с меньшей.
- Ховер: ±0.05–0.08 по L, не меняй hue.
- `color-mix(in oklch, var(--accent) 12%, var(--bg))` — для мягких подложек/бейджей.
- Фолбэк не обязателен (OKLCH ~ 93%+ поддержки), но для старых Safari можно продублировать hex строкой выше.
- Помни про гамут: oklch с chroma > ~0.15 на светлых L вылезает за sRGB — проверяй в oklch.com.

## 3. Контраст и доступность мягких палитр

WCAG 2.2 AA: **4.5:1** обычный текст, **3:1** крупный (≥24px или ≥18.66px bold), **3:1** для UI-элементов и значимой графики (границы полей, иконки, фокус). AAA: 7:1 / 4.5:1.
- Бежевое на кремовом почти всегда проваливает. Мягкость создаётся **фонами и поверхностями**, а не бледным текстом.
- Основной текст: L ≤ 0.30 на светлом фоне (≈ 10–14:1). Вторичный: L ≈ 0.50–0.55 (проверять ≥4.5:1). Плейсхолдеры — тоже 4.5:1, если они несут смысл.
- Акцентная кнопка: белый текст на акценте требует L акцента ≲ 0.58 (для терракоты/шалфея). Пастельный акцент → тёмный текст на нём, не белый.
- Ссылки в тексте не различаются только цветом: подчёркивание (`text-underline-offset: .2em; text-decoration-thickness: 1px`).
- Текст на фото: гарантируй контраст оверлеем `linear-gradient(to top, oklch(0.15 0.02 var(--h)/.55), transparent 60%)` или размещай текст на спокойной зоне кадра. Проверяй по самому светлому пикселю под текстом.
- APCA (кандидат WCAG 3) лучше оценивает тёмные темы и тонкие шрифты: для body ориентир Lc ≥ 75, для крупных заголовков Lc ≥ 60. Используй как вторую проверку, AA — как обязательную.
- Тонкие шрифты (300 и ниже) на мягком контрасте — главный провал «премиальных» сайтов. Light только ≥ 32px.

## 4. Нишевые палитры

| Ниша | Работает | Клише / избегать |
|---|---|---|
| Пилатес / wellness | Глина, овсянка, тёплый камень + шалфей или глубокий оливковый; либо бетон + шоколад. Тёмные секции — эспрессо, не чёрный | Мятный + белый «как у всех», бирюза-спа, градиенты сиреневый-розовый, бамбук/камни |
| Флорист | Нейтральный (бумага, лён, серо-зелёный) — цветы дают цвет сами. Акцент — один тон из сезонного букета или глубокий бордо/мох | Розовый на розовом, нежно-пудровый весь сайт, скрипт-шрифты + розочки; яркий акцент конкурирует с цветами |
| Парфюм | Монохром вокруг ноты: янтарь/табак (тёплые), дымчатый синий/графит (свежие), молочно-кремовый (мускус). Много тёмного, мало элементов | Золото-на-чёрном с блёстками, фиолетовая «роскошь», хром-градиенты |
| Хоспиталити / отель | Цвета места: известняк, терракота, морская вода, дуб. Тёмный вечерний вариант для ресторана/бара | Тёмно-синий + золото «бизнес-отель», стоковая бирюза моря |
| Еда / ресторан / кофе | Тёплые тёмные (жжёный сахар, томат, оливка, чернильно-зелёный) — аппетит; фуд-фото на тёплом фоне | Холодные синие и серые фоны вокруг еды, неон, красно-жёлтый фастфуд для премиум |
| Бьюти / skincare | Кожа-тона (персик, песок, роза-нюд) + чистый офф-вайт; или клинический бело-холодный с 1 цветным акцентом | Весь сайт миллениал-пинк, glossy 3D-капли, перламутровые градиенты |
| D2C товар | Цвет продукта/упаковки как акцент, всё остальное нейтрально; допустимы смелые цветовые блоки за продуктом | 5 ярких цветов «весело», градиент на каждой кнопке |

Общий признак клише: цвет выбран «по ассоциации с нишей», а не из фото и характера конкретного бренда. Спроси: «отличу ли я этот сайт от конкурента, закрыв логотип?»

## 5. Ритм тёмных/светлых секций

- Базовая страница светлая; 1–3 тёмные секции как «вдох»: манифест/философия, отзыв/цитата, финальный CTA или футер.
- Не чередуй свет/тьма каждую секцию — получается зебра. Паттерн: С С Т С С Т(футер) или С С С Т С.
- Между светлыми секциями — смена поверхности (--bg ↔ --surface, разница L 0.02–0.04), а не линии.
- Тёмный — из hue бренда (L 0.18–0.24, chroma 0.015–0.03), не #000/#111. Текст на тёмном — офф-вайт L≈0.93, не чистый белый (меньше «свечения»).
- На тёмном: уменьши насыщенность акцента или подними L, иначе он «горит». Тонкие шрифты на тёмном визуально тоньше — +1 шаг weight или +letter-spacing.
- Фото в тёмной секции — низкоключевые (low key) кадры, иначе светлое фото «вырезает дыру».
- Переход в тёмную секцию можно сделать полноэкранным фото как мостом.

## 6. Арт-дирекшн: единство съёмки

**Одна локация, один свет, одна палитра одежды/реквизита** — главное, что отличает премиум от стока.
- Свет: выбери один сценарий на весь сайт (мягкий боковой дневной свет из окна, ~10–11 утра или золотой час) и не смешивай со вспышкой/студийным белым фоном.
- Цветокор: один пресет на все фото (баланс белого, кривые, теневой тон). Тени — с тем же hue, что и тёмные секции сайта.
- Реквизит и одежда — в палитре сайта (2–3 тона). Запрещай логотипы, яркие принты, белые кроссовки, если не в концепции.
- Серия: 1 «геройский» кадр-атмосфера, 3–5 деталей (руки, фактуры, продукт крупно), 2–3 кадра людей в процессе, 1–2 пространства (общий план).
- Человек vs продукт: wellness/хоспиталити/бьюти-услуги продают **ощущение** → люди в процессе, не смотрят в камеру, частично в кадре (руки, плечо, спина). D2C/парфюм/флорист → продукт герой, люди как масштаб и контекст. Лица в камеру — только для команды/основателя.
- Взгляд и направление: человек смотрит/движется в сторону текста или CTA.

### Кропы и пропорции
- Ограничь набор: например 4:5 (портрет), 3:2 (горизонт), 1:1 (детали), 16:9 или 21:9 (hero/баннер). Не больше 3–4 пропорций на сайте.
- Задавай `aspect-ratio` + `object-fit: cover` + `object-position` осознанно (лицо/продукт не обрезать на мобильном). Для разных брейкпоинтов — `<picture>` с другим кропом (art direction через `media`).
- Смелые кропы = премиум: обрезанное лицо по глаза, деталь на весь экран, много пустого пространства в кадре под текст.
- Негативное пространство в hero-кадре закладывается на съёмке/генерации: «subject on right third, empty wall on left».
- Сетка фото: разные размеры, но общий горизонт/линия глаз; без рамок, теней и скруглений >8px у фотографий в премиум-стиле (или единый радиус везде).

## 7. Бриф для фотосъёмки / AI-генерации, чтобы выглядело реально

Структура промпта/брифа: **сюжет → действие → локация → свет → камера/объектив → плёнка/зерно → палитра → несовершенства → кадрирование.**

Пример:
> Editorial photo of a woman in her 30s stretching on a reformer in a pilates studio with limewash walls and oak floors, mid-movement, not looking at camera. Soft window light from the left, late morning, gentle shadows. Shot on 35mm, 50mm lens at f/2, eye level, shallow depth of field. Kodak Portra 400 tones, fine film grain, slightly muted warm palette of clay, oat and sage. Natural skin texture with pores, flyaway hair, wrinkled linen, a water bottle slightly out of focus. Subject on right third, empty wall on the left. Vertical 4:5.

- Объектив: 35–50 мм для людей/пространства (естественная перспектива), 85–100 мм портрет/детали, macro для фактур. Указывай диафрагму и высоту камеры.
- Свет словами фотографа: «window light, overcast daylight, golden hour backlight, practical lamps, hard noon sun with crisp shadows» — конкретика вместо «beautiful lighting».
- Плёнка/камера: Portra 400, Fuji 400H, Cinestill 800T (вечер), «shot on Leica / Contax T2» — даёт зерно и мягкий тональный отклик.
- Несовершенства — обязательно: поры, мелкие волоски, складки ткани, крошки, капли, пыль в луче, слегка смазанное движение, неидеальная симметрия, следы использования.
- Запрещай: «perfect, flawless, ultra-detailed, 8k, hyperrealistic, studio lighting, octane render» — это делает «пластиковую» AI-эстетику.
- Консистентность серии: одинаковый блок «свет+камера+плёнка+палитра» во всех промптах; reference-изображение (image prompt / style reference) + фиксированный seed; одна и та же модель/персонаж через reference.

### Типичные AI-признаки и исправления
| Признак | Как избежать / исправить |
|---|---|
| Пластиковая гладкая кожа, «восковое» лицо | Промпт про текстуру кожи, без «flawless»; добавить зерно 2–4% в постобработке |
| Руки/пальцы, лишние суставы | Руки в кармане/за предметом/вне кадра; inpaint рук; кроп |
| Текст, логотипы-каракули | Убрать надписи из промпта, закрасить/inpaint, нужный текст накладывать в HTML |
| Идеальная симметрия, центр кадра | Явно задать композицию по третям, наклон, кроп |
| Перенасыщенный HDR, оранжево-бирюзовый грейд | «muted, low contrast, natural color»; в постобработке снизить vibrance, поднять чёрные |
| Свет из ниоткуда, нет теней/контакта с поверхностью | Указать источник; проверить контактные тени у ног/предметов |
| Фон с размытой «кашей», нелогичная архитектура | Простая локация, проверить линии, кроп или inpaint |
| Одинаковые «AI-лица» | Указать возраст, этничность, черты, неидеальность; реальные референсы |
| Слишком чисто — ни одной лишней вещи | Добавить быт: чашка, сумка, крошки, мятый плед |
| Странные детали: украшения, швы, лепестки сливаются | Зум 200% каждой картинки перед публикацией |

Постобработка всех AI-кадров одинаково: единый LUT/кривая, лёгкое зерно, чуть приподнятые тени, небольшая виньетка — склеивает серию и убирает «цифровой» лоск.

### Апскейл
- Генерация обычно 1–2 Мп → апскейл ×2–×4 (Topaz Gigapixel/Photo AI, Magnific, Real-ESRGAN, Krea) до ширины ≥ 2560 px для hero.
- Режимы «creative/hallucination» держи низкими — иначе появляются новые артефакты и пластик; для лиц — отдельный слабый face-restore.
- Апскейл делается **до** цветокора и зерна; зерно добавляется последним (апскейл его размажет).
- Не выкладывай в оригинальном размере: финальный экспорт — под реальные размеры показа (см. п. 9).

## 8. Видео или фото в hero

Видео — когда **движение и есть продукт/ощущение**: вода в отеле, текучее движение в пилатесе, пар над кофе, ткань, процесс сборки букета. Фото — когда важна композиция, продукт, скорость, или видео-материал среднего качества (плохое видео хуже хорошего фото).
- Hero-видео: 6–15 с, бесшовный луп, медленное движение без резких склеек, без текста в кадре, без звука (`muted autoplay loop playsinline`), спокойная зона под заголовок.
- Всегда `poster` (первый кадр, оптимизированный AVIF/WebP) — он и есть LCP-кандидат.
- `prefers-reduced-motion: reduce` → показывать poster, видео не запускать. Нужна кнопка паузы, если движение > 5 с (WCAG 2.2.2).
- На мобильном рассмотрите отдельное, более лёгкое вертикальное видео или только фото.
- Альтернатива видео: синемаграф (одна движущаяся деталь), медленный CSS Ken Burns по фото (`transform: scale` 1→1.06 за 20 с).

## 9. Бюджеты производительности

- LCP ≤ 2.5 с (p75 на мобильном), CLS ≤ 0.1. Hero-изображение — главный LCP-элемент.
- Hero-фото: AVIF ≤ 150–250 КБ (десктоп 2560w), ≤ 80–120 КБ (мобайл 828–1080w). Остальные фото ≤ 100–200 КБ, миниатюры ≤ 40 КБ.
- Вес всей страницы-визитки: ориентир ≤ 1.5–2 МБ без видео.
- Hero-видео: ≤ 2–3 МБ десктоп (1080p, H.264 + WebM/AV1, CRF ~28, без аудиодорожки), ≤ 1 МБ мобайл (720p) или не грузить.
- Разметка:
```html
<img src="hero-1600.avif" srcset="hero-828.avif 828w, hero-1600.avif 1600w, hero-2560.avif 2560w"
     sizes="100vw" width="2560" height="1600" alt="…" fetchpriority="high" decoding="async">
<!-- все ниже первого экрана: loading="lazy" -->
<video autoplay muted loop playsinline preload="metadata" poster="hero-poster.avif">
  <source src="hero.webm" type="video/webm"><source src="hero.mp4" type="video/mp4">
</video>
```
- Всегда `width`/`height` или `aspect-ratio` (без CLS). Hero не lazy. `<picture>` с AVIF → WebP → JPEG.
- Плейсхолдер: фон-цвет = средний цвет фото (`background: oklch(...)`), а не серый.
- Цветовой профиль: экспорт в sRGB (Display P3 только намеренно, с проверкой).
- `alt`: описывай смысл кадра, декоративные — `alt=""`.

## 10. Чеклист аудита

**Цвет**
- [ ] Палитра выведена из фото; hue нейтралей = hue бренда; нет чистого #000/#fff/серого
- [ ] Акцент ≤ ~5% площади, только на главных действиях, один hue
- [ ] Токены в OKLCH на `:root`, шкала с равными шагами L, ховеры ±L
- [ ] Текст ≥ 4.5:1, крупный ≥ 3:1, UI/границы полей/фокус ≥ 3:1; вторичный текст проверен отдельно
- [ ] Текст на фото читается на самом светлом участке (оверлей/зона)
- [ ] Ссылки различимы не только цветом; light-веса только на крупных кеглях
- [ ] Ритм секций без зебры; тёмные секции тёплые/брендовые, офф-вайт текст
- [ ] Палитра не нишевое клише — тест «закрой логотип»

**Изображения**
- [ ] Один свет, одна локация/серия, один цветокор во всех кадрах
- [ ] 3–4 пропорции максимум; кропы проверены на 375 px (лица/продукт не срезаны)
- [ ] Есть баланс: атмосфера / детали / люди в процессе / пространство
- [ ] AI-кадры проверены на 200%: руки, текст, украшения, контактные тени, кожа; добавлено зерно
- [ ] Нет стоковых клише (улыбка в камеру, рукопожатие, белый фон-студия вне концепции)
- [ ] Hero: видео оправдано, есть poster, reduced-motion, пауза

**Производительность**
- [ ] AVIF/WebP + srcset/sizes; размеры в атрибутах; hero `fetchpriority="high"`, остальное lazy
- [ ] Hero ≤ 250 КБ, видео ≤ 3 МБ; LCP ≤ 2.5 с, CLS ≤ 0.1 (Lighthouse, мобайл)
- [ ] Плейсхолдер — средний цвет фото; alt осмысленный

## Проверено по источникам 22.10
- Evil Martians, «OKLCH in CSS: why we moved from RGB and HSL» (evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl): у OKLCH светлота воспринимаемая (в HSL нет), поэтому палитру можно задать формулой; не все сочетания L/C/H отображаются на каждом мониторе — проверять гамут. Инструмент oklch.com.
- LCP (по пересказам web.dev и демо chrome.dev/f/learn_performance_video): постер видео — кандидат в LCP; fetchpriority="high" на 1–2 картинках или постере ускоряет (1.2 с против 1.7 с в демо); LCP-картинку никогда не делать lazy; картинка должна быть в HTML, а не в data-src или CSS, иначе нужен preload.
