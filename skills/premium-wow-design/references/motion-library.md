# Библиотека анимаций (HorizonX, обновляется еженедельно)

Главный источник движения — https://horizonx.so/explore (Вероника: «нравятся их анимации, стиль совпадает с Vistora»). Код у них платный (Premium) — **не скачиваем и не копируем**. Смотрим открытые превью-видео (cdn.horizonx.so/*.mp4), разбираем покадрово (ffmpeg `fps=6/длительность, tile`) и пишем свою реализацию на Three.js / GSAP / шейдерах.

## Правило Вероники: идея — да, копия — нет
Из референсов берём **идею движения**, а не сцену. Всегда менять минимум три вещи: поведение объекта (у Crest карта висит — у нас качается и наклоняется), композицию/свет/палитру, тексты и бренд. Итог подстраивается под бизнес клиента и его сайт. Тексты, логотипы, ассеты и код референса не переносить.

## Подбор под бизнес (не только свежие работы)
Перед каждым проектом пересобрать каталог (`python3 tools/horizonx_catalog.py`) и искать по **всему** каталогу `horizonx-catalog.md` по нише клиента (банк → финтех/карты/wealth/dashboard; парфюм → perfume/fragrance/botanical и т.д.), плюс новые ★. Смотреть превью **видео**, а не только стоп-кадры: ритм, физика, переходы.

## Проверка своих сцен — по видео
Записывать прокрутку `NODE_PATH=/tmp/pw/node_modules node tools/scene-rec.js URL папка` (CDP-скринкаст: 5 с покоя + проход, кадры с таймингами; Playwright recordVideo тут не работает — нет его ffmpeg), без reduced-motion, и смотреть кадры 4–8 в секунду: жив ли объект в покое, нет ли рывков, совпадает ли ритм с референсом. Стоп-кадры в reduced-motion не показывают движение.

## Если HorizonX не подходит бизнесу
HorizonX — первый, но не единственный источник. Если его стиль не подходит нише или балансу (тихая роскошь, медицина, юристы, детское, локальный сервис), сразу идти по остальным источникам из `research.md`: GSAP showcase, Codrops, Awwwards/godly/siteinspire по нише, motionsites, reactbits, 21st.dev, lenis showcase, refero/mobbin (для UX-паттернов). Критерий выбора — задача бизнеса и баланс «Премиальность / Вау», а не красота анимации сама по себе.

## Общие закономерности HorizonX
- Один герой-объект, вокруг — сцена-атмосфера (вода, туман, огонь, частицы); UI тонкий, мелкий, по краям.
- Скролл = главы фильма; текст главы короткий (2 строки) и меняется кроссфейдом.
- Частицы/точки — главный «тех»-приём; для премиума — мягкий туман, свет, отражения.
- Финал — гигантское слово-логотип или смена темы (светлое → чёрное).
- Соответствие нишам: парфюм/косметика — Lotus/Vallora; архитектура — Alder & Stone; ИИ/SaaS — Orvane/Sorvine/Emberline; одежда/техника — Cyber Jackets/ARQ; ремесло/часы — Watchmaker/Kiln.

## Учебные сцены (своя реализация, рецепты)
### 01 · Раскрытие цветка + флакон + погружение (по мотивам Lotus Perfume) — `projects/training/01-lotus-bloom/`
- Три.js без моделей: камень = IcosahedronGeometry(1.6, 6) → `mergeVertices` (иначе гранёный) → шум по вершинам, сплющить по Y.
- Лепесток = Shape из двух bezier → ShapeGeometry → «чашка» через z = x²·0.9 + y²·0.08. Три кольца 10/8/6, раскрытие rotation.x с задержкой по кольцам, лёгкое «дыхание» sin.
- Флакон: Cylinder 12 граней + flatShading, MeshPhysical transmission .82, ior 1.7, attenuationColor; золото metalness 1. Окружение RoomEnvironment через PMREM — без него стекло мёртвое.
- Море: шейдер-плоскость, волны в vertex, френель + блики только вдоль солнечной дорожки (тонкие штрихи, иначе «горошек»). DoubleSide: снизу — розовый потолок с мягкой рябью.
- Туман: Points с canvas-радиальным спрайтом, `fog:false, toneMapped:false` (иначе серый).
- Скролл = 4 главы: 0–.27 раскрытие, .25–.5 подъём, .48–.72 туман, .72–.95 погружение. Прогресс сглажен lerp .08 + Lenis. Камера: отступает при погружении (иначе пролетает сквозь камень), lookAt следует за флаконом.
- Под водой: туман и небо lerp в тёмный рубин, конусы-лучи additive opacity .05, тексты глав меняют цвет, меню светлеет (класс .deep).
- Ошибки, которые уже исправлены: полка-точки бликов, гранёный камень, серый туман, ранний текст последней главы, флакон «висит» над постаментом.

#### 01 · версия 2 — что подняло реализм (2026-10-19)
- **Фото вместо кода там, где нужен реализм.** Фон — сгенерированный в Figma (gemini-3.1-flash-image) рассвет над морем: задник-купол (шейдер берёт фото по направлению взгляда) + отражения в воде + envMap через PMREM. Флакон — сгенерированное фото на хромакее #00FF00 → вырезка (alpha = 1 − clamp((G − max(R,B) − 40)/80), despill G ≤ max(R,B)) → билборд, всегда повёрнут к камере; блик-софтбокс бежит по диагонали шейдером, внутри разгорается свет.
- Стекло из MeshPhysical в тёплом окружении выцветает в «лосось» — для героя-продукта брать фото.
- Мокрый камень: canvas-шум как bumpMap + roughnessMap, тёмный цвет, envMapIntensity 1.3 → ловит отблеск флакона.
- Постобработка: UnrealBloom (порог .92, сила .22–.6 по главам) + зерно и виньетка ShaderPass + OutputPass. Не называть переменную прогресса `bloom` (конфликт с пассом).
- Прозрачность морю не давать (тёмные штрихи на горизонте) — непрозрачный шейдер, даль уходит в цвет неба.
#### 01 · версия 3 — «доведено» (2026-10-19)
- Флакон «поворачивается»: карта глубины (`tools/depth.py`) → в шейдере билборда сдвиг UV = (depth − .55) · turn · .045; turn = sin(t) + мышь. Блик идёт по глубине (ближние грани первыми). Полный 360° — только моделью или видео Higgsfield.
- Лепестки: сгенерированный лепесток на хромакее → текстура с alphaTest .4 на изогнутой ShapeGeometry (UV = нормированные x/y формы). Реализм в разы выше «чистого 3D».
- Круги на воде при подъёме: аддитивная плоскость-шейдер, кольца fract(r·.55 − t·.25) между r 2–9, сила = rise.
- Под водой: фото-подложка (сгенерированная: рубиновая вода, лучи) в том же куполе, mix по `under`; потолок воды снизу прозрачнеет с расстоянием (иначе жёсткая линия); SpotLight на центральный постамент — продукт-герой подсвечен.
- Проверять покадрово 8 точек скролла + телефон. Искать: «горошек», швы горизонта, висящий над постаментом продукт, пересвет bloom, текст поверх продукта.

### 02 · Облако частиц с морфингом (по мотивам Orvane / Sorvine / Alder & Stone) — `projects/training/02-particles/`
- Одна `Points` из 24 000 точек (12 000 на телефоне), 4 целевые формы в атрибутах aA..aD: сфера, слово (точки из пикселей canvas с текстом), галактика (3 рукава, плотнее к центру), планета с кольцом.
- Морфинг в вершинном шейдере: `stage` 0..3 от скролла, у каждой точки сдвиг по seed (±.17) — переход «волной». Турбулентность (value-noise flow) максимальна между формами и затихает, когда форма держится. Скролл «ступенчатый»: форма держится ~35% главы, потом мягкий переход.
- Курсор раздвигает облако: точка пересечения луча с плоскостью z=0, отталкивание exp(−d²·1.6).
- AdditiveBlending, мягкий круг в фрагменте, bloom (порог .1, сила .45–.8). Цвет: холодный синий → белый по яркости, тёплое ядро у планеты.
- Форма уходит от колонки текста (галактика вправо, планета влево) — иначе частицы ложатся на заголовок.
- Подходит: ИИ, SaaS, финтех, наука, космос, музыка. Не подходит: тихая роскошь, еда, медицина.

### 03 · Продукт в воде + смена настроения (по мотивам Crest Water) — `projects/training/03-water/`
- Вода = `Reflector` (настоящее зеркало) со своим шейдером: рябь смещает UV отражения (амплитуда ≤ .002, иначе «плавит» отражение), кольца вокруг продукта, даль уходит в цвет горизонта (иначе рваная линия).
- Reflector **клонирует uniforms** — цвет обновлять через `water.material.uniforms.X.value.copy()`.
- Небо — градиент-шейдер с солнцем за продуктом; 3 палитры (ember/violet/lagoon) lerp по скроллу; кольцо, метка на карте, подсветка и вода берут цвет палитры.
- Продукт: RoundedBox из стали (metalness .9) + лицевая/оборотная сторона из canvas (портретная раскладка!). Скролл: выход из воды → поворот на оборот → смена неба → возврат лицом для оффера.
- Пересвет: exposure .82, солнце узким пятном (pow 220), bloom порог .9. Ключевой свет спереди, иначе продукт — силуэт.
- **Жизнь в воде (v2, после замечания Вероники):** продукт качается (bob sin 1.1 Гц ±.07 + мелкая гармоника), покачивается по z/x; от него бегут кольца sin(d·4.2 − t·3.2)·exp(−d·.45) в UV отражения + блик на гребнях; общая медленная зыбь. Без этого сцена «мёртвая».
- Светящийся круг под продуктом (additive) держать ≤ .03 — иначе с bloom даёт белое пятно; отражение затемнять (refl·.72 + tint .3).
- Проверять движение без reduced-motion (в reduced-motion t=0 — анимацию не видно).
- **v3, сверено с видео Crest:** карта висит над водой (не в воде), наклоны ±.09 по z и ±.14 по y с двумя гармониками; лицевая сторона — шейдер: чёрный → цвет настроения → яркий край + блик, который бежит по наклону; кольцо — тонкая тёмная линия (не свечение); под картой яркие кольца от наклона «нормали» ряби (sun spec), по воде длинные горизонтальные штрихи ряби (точечная рябь = «горошек»). Цвета в ShaderMaterial переводить в линейные (pow 2.2), иначе пересвет.
- Для финтеха, техники, часов, украшений, напитков.

### 04 · Туннель из карточек (по мотивам Yohaku Tunnel) — `projects/training/04-tunnel/`
- 24 постера на внутренней стороне цилиндра (R=6); геометрия каждого изогнута по окружности (x → sin(x/R)·R, z → R − cos(x/R)·R). Камера чуть позади центра (z 2.2) смотрит на стену — края уходят, получается туннель.
- Скролл вращает кольцо (1.5 оборота) + медленный дрейф; наклон по скорости (rotation.z = скорость · .4) — лента «изгибается» на бегу; курсор наклоняет взгляд.
- Ховер: Raycaster → постер выдвигается к зрителю и чуть растёт. Туман цвета бумаги растворяет края.
- Постеры генерируются на canvas (цифры, круги, полосы, serif/grotesk) — для реального проекта заменить работами клиента.
- Для студий, портфолио, галерей, коллекций, каталогов.

## Сцена 05 — настоящий 3D-флакон со стеклом (projects/training/05-glass-flacon)
- Стекло: MeshPhysicalMaterial transmission 1, thickness ~1.1, ior 1.52, roughness .04, лёгкий attenuationColor (зелень толстого стекла), envMapIntensity ~.55.
- Отражения без HDR-файла: PMREMGenerator + RoomEnvironment → scene.environment.
- За флаконом обязательно фон с крупной типографикой/линиями — иначе преломления не видно и стекло читается как пластик. Фон приглушить (#B8A992 на #ECE5D8), чтобы подписи сверху читались.
- Жидкость внутри — НЕ transmission (вложенная прозрачность исчезает): тёмный янтарь + emissive (свет изнутри) + clearcoat. Делать меньше корпуса, чтобы читалась толщина стенок.
- Тонмаппинг: ACES делает кремовый фон за стеклом серым → NoToneMapping для светлых сцен.
- Латунь: metalness 1, roughness ~.28, envMapIntensity 2 — иначе на крупном плане коричневая.
- Тень: радиальный градиент на плоскости вместо shadow map. pixelRatio ≤1.5 (transmission рендерит сцену дважды).
- Прокрутка: 4 «бита» камеры (общий план → стекло → крышка → покупка), подписи меняются по биту; подсказка «Scroll» исчезает после первой прокрутки.
- Не забывать <meta charset="utf-8"> в тренировочных файлах (без него € и · ломаются).
- v2 (доводка до готового):
  - Жидкость с живым уровнем: мировая clipping plane (renderer.localClippingEnabled) срезает тело жидкости; поверхность — отдельная скруглённая плоскость того же сечения, ориентированная по той же плоскости в локальных координатах флакона. Трюк «задние грани как поверхность» даёт мятую кромку — не использовать.
  - Плескание: пружина (k 40, d 4) с толчком от скорости поворота, считать подшагами по реальному времени — иначе на слабом устройстве жидкость не успокаивается.
  - Все сглаживания (прокрутка, курсор) — по времени: 1 − exp(−dt·k), не «×0.07 за кадр».
  - Толщина transmission ~.55: при 1.1 кромка жидкости двоится и рвётся.
  - Металл латуни: metalness ~.82 — чистый металл без хорошего окружения выглядит коричневым.
  - Каустика: мягкое янтарное радиальное пятно, без белых линий и без additive — сбоку они превращаются в «баг-полосу».
  - Защита слабых устройств: замер 8 кадров → pixelRatio 1 → отключить Lenis (иначе на 3 fps прокрутка встаёт полностью — в headless swiftshader это и поймали).
  - Телефон: setViewOffset поднимает флакон в верхнюю часть, камера отходит ×1.5, подписи на градиентной подложке снизу.
  - QA прокрутки — колесом мыши (mouse.wheel), а не scrollTo: scrollTo обходит Lenis и прячет баги.
- v3 — настоящая каустика и капли:
  - Каустика по методу Evan Wallace: сетка 384² «фотонов» (PlaneGeometry) в отдельной сцене рендерится в HalfFloat-таргет 768² с AdditiveBlending. В вершинном шейдере каждый луч: sphere-tracing SDF флакона (скруглённый бокс) и крышки → refract внутрь (1/1.52) → марш внутри по −SDF, считая путь через янтарь → refract наружу (при полном внутреннем отражении — reflect и ×0.35) → пересечение со столом. Яркость = площадь до / площадь после (dFdx/dFdy от vOld/vNew), clamp 4.
  - Свет — сзади-сверху, чтобы узор падал к зрителю. Поглощение янтаря exp(−L·(.2,1.3,3.2)).
  - Стол = цвет фона; E=1 → ровно фон, E<1 → тёплая тень (никогда не серая), E>1 → подсветка. 9-tap размытие прячет сетку лучей; к краю патча — плавный переход в фон.
  - Типографика на стене стоит базовой линией на столе (иначе стол «режет» буквы).
  - Капли: InstancedMesh сплющенных сфер с transmission (ior 1.33). На светлом фоне без тёмной кромки они невидимы → onBeforeCompile: затемнить по Fresnel (facing). Три «бегуна» stick-slip (ускорение → случайные остановки), оставляют дорожку бусинок, считаются по реальному времени.
  - Проверять бегущие капли на крупном плане и численно (временный window.__runners), на общем плане капля ≈7 px.

## Сцена 06 — шёлк, который снимают с украшения (projects/training/06-silk-unveil)
- Verlet-ткань на CPU: 48² частиц (36² на телефоне), связи structural 1 / shear .7 / bend .12 (шёлк легко складывается), 6 итераций, фикс. шаг 60 Гц (max 3 шага за кадр). Предпрогон 260 шагов — ткань уже лежит к первому кадру.
- Коллайдеры: плоский эллипсоид по форме предмета (под тканью читается то, что спрятано), цилиндр подиума с зазором .05 (иначе камень «прорастает» сквозь треугольники), пол.
- Трение обязательно: при касании O += (P−O)·.85, иначе шёлк стекает с любых выпуклостей.
- «Рука»: средняя частица закрепляется и едет по пути от прокрутки (вверх-вправо, полностью из кадра).
- Обратная прокрутка: после отпускания 1.4 с сильная тяга к сохранённой драпировке DRAPE и отключённый коллайдер предмета — иначе ткань ложится ПОД кольцо. Потом слабая «память формы» .0035.
- Курсор = палец: только нажим вдоль луча камеры (гаусс по расстоянию до луча), никакого бокового таскания — сфера-коллайдер у курсора сдёргивает всю ткань.
- Материал: MeshPhysical sheen 1, sheenRoughness .32, светлый sheenColor; тени PCFSoft от spot.
- Камни на тёмном фоне: transmission даёт чёрный камень → ступенчатая огранка LatheGeometry (8 граней) + flatShading + emissive + clearcoat.

## Сцена 07 — дым благовоний (projects/training/07-smoke)
- Stable fluids на GPU (three.js, HalfFloat-таргеты, полноэкранный квад, ping-pong): curl → vorticity confinement (k≈22) → divergence → давление (fade .8 + 22 итерации Jacobi) → вычитание градиента → адвекция скорости (с плавучестью и ветром) → адвекция «краски» (дыма). Сетка скорости 128, дыма 640 (по аспекту).
- Нить благовония: узкая быстрая струя (скорость 150, радиус сплэта 3e-5) + плавучесть 700·плотность → внизу ламинарная, выше рвётся в завитки. Медленная струя = облако у источника.
- Курсор толкает воздух (сплэт скорости = смещение ×5200) и тянет немного дыма; быстрая прокрутка = сквозняк (ветер по X от скорости скролла).
- Отрисовка: оптическая плотность 1−exp(−d·4), свет сверху, уголёк и палочка в том же шейдере, плёночное зерно против бандинга. Цвета задавать как display-значения и НЕ включать colorspace_fragment — иначе тёмный фон становится серым.
- Главы прокрутки меняют цвет дыма (аромат) — физика та же, бизнес-смысл новый.
- Reduced motion: «запечь» 6 секунд симуляции и держать кадр; при пересоздании буферов (resize, защита слабых устройств) запекать заново — иначе кадр пустой.

## Правка по реализму (отзыв Вероники, 2026-10-20) — главное правило для любой 3D-сцены
- Эффект должен вести себя как в жизни, а не «показывать технологию». Проверка: похоже ли это на видео настоящего предмета?
- Каустика: тонкие яркие линии = «лазер». Солнце — диск: лучей больше пикселей карты (≈3 на пиксель, иначе муар) + отдельный гауссов блюр в 2 прохода + низкий пик яркости (≤2.2). Пересчитывать только при заметном повороте.
- Конденсат: тысячи микрокапель (морось на canvas-текстуре) + средние капли; бегущая капля растёт, сливаясь с встречными, стирает за собой чистую дорожку (destination-out линией между прошлой и текущей позицией), дорожка-бусинки высыхают, морось возвращается за ~10 с. Ячейки InstancedMesh, которые ещё не заняты, прятать масштабом 0 (по умолчанию они — единичные шары!).
- Дым: курсор только двигает воздух (широко и мягко), никогда не «рисует» дым; мягкие края (смесь с блюром), слабая завихрённость (≈9), нейтральный серо-голубой цвет с намёком на аромат, медленный подъём.
- Ткань: не тянуть невидимой точкой («фильм ужасов»). Естественная причина движения — ветер: порывы, сильнее на свободных краях, трение отключается, ткань улетает; при возврате — тяга к драпировке по времени симуляции.
- Фото: никаких «капель/искажённых зеркал». Премиальный ховер — лёгкий наезд и медленный дрейф за курсором (окно), изгиб от скорости — едва заметный.
- Превью-хостинг блокирует fetch (в т.ч. data:): модели — JS-модулем + текстуры через <img> (TextureLoader). Локально тестировать через сервер с CSP connect-src 'none' (/tmp/claude-0/srv/csp.py), чтобы ловить это до Вероники.

## Сцена 10 — персонаж со скелетом, управляемый прокруткой (projects/training/10-fox-walk)
- Модель: Khronos Fox (CC0 + CC BY 4.0 → подпись авторов на странице), клипы Survey / Walk / Run. Конвертер tools/glb2js.py (любой .glb → JS-модуль + webp-текстуры для превью).
- AnimationMixer: все клипы играют, смешиваются весами по скорости: стоит → осматривается, медленно → шаг, быстро → бег; веса сглажены. ГЛАВНОЕ для реализма: timeScale = скорость по земле / «родная» скорость клипа → лапы не скользят.
- Направление: разворот по знаку скорости, поворот плавный (atan2 разности углов), путь — кривая, персонаж смотрит по касательной.
- Трава: 70k травинок (22k на телефоне) одним InstancedMesh + ShaderMaterial (instanceMatrix доступен): ветер двумя волнами, корень неподвижен, кончик ходит (h²); персонаж раздвигает траву (uniform с его позицией); цвет от тёмного корня к светлому кончику + контровой свет; туман вручную во фрагменте.
- Нельзя ставить траву прямо перед камерой (гигантские полосы); камера — длиннофокусный «трекинг» чуть выше травы.
- Текст поверх сложной фактуры — на полупрозрачной панели с backdrop-filter, а не тенью.

## Сцена 11 — проход по архитектуре (projects/training/11-villa-flythrough)
- Камера идёт по CatmullRom-сплайну на высоте глаз (1.6 м), отдельный сплайн — куда смотреть; getPointAt по прогрессу прокрутки с тяжёлым сглаживанием (шаг человека, не дрон) + «ручная камера»: медленное дыхание и дрейф.
- Свет: Sky (физическое небо) как фон И как окружение (PMREM из второй копии неба), низкое солнце перед стеклянным фасадом, ACES с экспозицией ~.55.
- Реализм интерьера даёт в первую очередь ambient occlusion (GTAOPass) — тени в углах и под мебелью; на телефоне выключен.
- Материалы процедурные (canvas): бетон с линиями опалубки, дубовые доски, плитка, штукатурка. Газон — ShapeGeometry с вырезом под бассейн (иначе трава сквозь воду).
- Стекло: почти прозрачное (opacity .1), иначе на просвет «молочное».
- Честно: процедурная вилла читается как макет архитектора; фотореализм для клиента = готовая модель от архитектора (glTF/IFC→glTF) или Gaussian splat снятого дома — та же камера и тот же сплайн к ним подходят.

## Сцены 12–13 — фотореализм из сгенерированных кадров (Figma AI + карта глубины)
- Когда нужен «как фото» результат быстрее, чем 3D-модель: сгенерировать 3–4 ключевых кадра в Figma (gemini-3.1-flash-image, один промпт-стиль: объектив, свет, время суток), карта глубины tools/depth.py (Depth Anything V2), webp.
- Движок (один WebGL-шейдер, без three.js): cover-fit, «наезд камеры» — пиксель смещается от центра пропорционально близости (3 итерации поиска глубины), курсор наклоняет вид, поле 6% против краёв; локальное дрожание воды/травы по полосе uv.y.
- Переход между кадрами: следующий кадр начинает с «шага назад» (push −1.15) и идёт навстречу; растворение в порядке глубины — дальнее уходит первым, как проход в дверь. Подписи — по Math.round(прогресса).
- Ограничение: в кадре нет настоящей анимации тела (лиса не двигает лапами) — для этого видео (Higgsfield) или 3D-риг. Этот способ = премиальный «живой» фото-скролл.

Держать его едва заметным (≈.12·глубина), без растворения по глубине и без дрожания травы. Настоящий проход/движение животного = видео, привязанное к скроллу (все кадры ключевые: ffmpeg -g 1), 360°-номера = панорамы/Gaussian splat.

## 3D-стакан с напитком (Layo, 2026-10) — `projects/matcha/site/cup3d.js`
- Three.js r160 через importmap (jsdelivr). Стакан: LatheGeometry с подвёрнутым краем, прозрачный пластик = MeshPhysical opacity .14 + clearcoat + RoomEnvironment (transmission делал жидкость мутной — не использовать для тонкого пластика поверх яркой жидкости).
- Жидкость: один lathe + ShaderMaterial (DoubleSide): слои по высоте, границы искажены 3D-fbm (матча «языками» уходит в молоко), нити матчи в молоке, тени льда, пюре с мякотью/семечками; верх — диск пены; лёд — полупрозрачные кубики на поверхности. 2D-шум по углу даёт полосы и шов — только 3D-шум по позиции.
- Уровни слоёв — пружины с подшагами; dt ограничивать ≤0.1 и ≥0, иначе на слабом железе анимация «замирает».
- Смена вкуса в hero — стакан уезжает и приезжает (цвет не меняется на месте — реализм). В конструкторе: фрукты падают и тонут, молоко/матча льются струёй.
- Блики софтбокса — мягкие и слабые (урок «лазер» повторился бы при узких ярких полосах).
- В headless (swiftshader) WebGL ~1 кадр/с: логику проверять с reducedMotion, визуал — скриншотами.
- v2 (по референсу The Matcha Club, Pinterest): слои = реальные текстуры, вырезанные из сгенерированных фото (tex/*.jpg, MirroredRepeat по углу, растяжение по высоте слоя); оттенок ингредиента — только мягкий сдвиг яркости/тона (поканальный ratio даёт синеву). Матча льётся из керамической катакути (lathe + носик), облака матчи в молоке (uniform cloud, fbm, затухает в нити). Логотип печатается белым на стенке (CanvasTexture из SVG, LatheGeometry phiStart=π → фронт u=.5). Стакан покачивается ±0.3 рад, а не вращается — печать всегда видна. Поверхность показывает текущий верхний слой.
- Логотип на фото продукта: белый SVG → PNG (playwright omitBackground) → цилиндрический изгиб (x→R·sin) → наложение 80% opacity на свободную часть стакана.

## «Живое фото» вместо 3D (Layo v3) — когда нужен фотореализм еды/напитков
- Вывод: реалтайм-3D жидкости выглядит как графика. Для фотореализма — композитинг реальных фото: на каждый напиток 3 совмещённых кадра (пустой стакан со льдом → молоко поверх фрукта → готовый), выровненных построчно по стенкам стакана (`tools/build_live.py`).
- Анимация = маски: пюре и молоко поднимаются волнистой кромкой; матча проявляется маской из шума, «языки» опускаются вниз (как в референсе The Matcha Club). Падают вырезанные фото настоящих кусочков фруктов; льются сфотографированные молочник и катакути (стрим обрезается по поверхности).
- Генерация: один стиль кадра для всех (прозрачный стакан, фронт, белый фон), кусочки фруктов — «разложенные отдельно на белом», затем авто-разрезка по компонентам.
- Логотип печатаем на все кадры одинаково (цилиндрический изгиб), чтобы стакан не «менялся».

## "Living photo" without video (Petal House, 23.10)
When there are no credits for video: one photo + its depth-map mask (tools/depth.py; for an uneven wall subtract the column baseline: 15th percentile of the column + 0.07).
- Layers: photo → word → foreground (the same photo with an alpha mask) → tint (multiply) → `.sun` (a warm radial-gradient, soft-light, drifts slowly 18s alternate).
- Parallax on the pointer: the foreground moves ±18px, the word ±7px, the background stays still → 2.5D depth; only with pointer:fine, off with reduced-motion.
- Changing the shot: a circle mask opens from the vase (clip-path circle 0→140%, 0.95s), the word's letters recolour with a delay of 45ms per letter.
