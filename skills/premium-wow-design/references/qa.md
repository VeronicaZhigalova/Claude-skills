# Технический аудит перед сдачей (QA)

Прогоняю после `critique.md`. Всё, что не проходит, исправляю до показа.

## 1. Скорость (Lighthouse / Core Web Vitals, скилл ship-check)
- LCP (первый экран) < 2.5 с; CLS (сдвиги) < 0.1; INP (отклик) < 200 мс; Lighthouse Performance ≥ 90 на мобильном профиле.
- Картинки WebP/AVIF, у каждого <img> width/height, всё ниже первого экрана — loading="lazy"; главный кадр — preload, без lazy.
- Шрифты: preconnect, display=swap, не больше 2 семейств и 4 начертаний.
- Вес страницы без картинок < 300 КБ JS+CSS.

## 2. Сдвиги и вёрстка
- Ширины 320 / 390 / 768 / 1024 / 1440 / 1920: нет горизонтального скролла, ничего не налезает и не обрезается.
- Кнопки/текст не прыгают при загрузке шрифтов и при анимациях (анимируется только transform/opacity).

## 3. Анимации и скролл
- Запись производительности при прокрутке (Playwright/DevTools trace): нет длинных задач > 50 мс, 60 fps.
- Pin/scrub не «дёргаются» при быстром скролле и ресайзе; ScrollTrigger.refresh после загрузки картинок.
- Canvas/WebGL останавливаются вне экрана; prefers-reduced-motion выключает всё движение.
- На телефоне тяжёлые эффекты (курсор, 3D, параллакс) отключены или упрощены.

## 4. Доступность (a11y-enforcer)
- Контраст AA, видимый фокус, вся навигация с клавиатуры, alt у фото, aria у интерактивного.

## 5. Контент и SEO-база
- title, meta description, Open Graph-картинка, favicon, lang, один h1, логичные h2.
- Нет битых ссылок и заглушек «#» в финале; формы с понятными ошибками.

## 6. Ограничения — честно сообщать
- Тестирую в Chromium. Safari/iOS и реальные устройства не проверяю — просить Веронику открыть на iPhone.
- Реальные интеграции (бронирование, оплата, CMS) — вне вёрстки, указывать отдельно.

## Уроки аудита Ombra (2026-10)
- Шейдеры (дым, живой кадр): рендер в пониженном разрешении (дым ×0.6, кадр ≤1.5 DPR, ≤2.2 Мпикс), ~30 fps без движения мыши, ничего не рисовать до начала сцены, fbm 4 октавы. TBT десктопа упал с 25 с до 0.
- Шрифты Google: preload + `media="print" onload` + noscript — FCP на телефоне 3.1 → 1.1 с.
- Анимации ниже первого экрана (Lenis/GSAP) запускать после load + requestIdleCallback.
- Если первый экран стартует с opacity 0, Lighthouse пишет NO_LCP: начинать с opacity .02. Постер у скрытого видео не ставить — он становится поздним LCP.
- Затемнённые «ещё не зажжённые» слова тоже должны держать 3:1 для крупного текста.
- Декоративное видео — `tabindex="-1"` (играющее видео Chromium делает фокусируемым).
- После любой правки скриптов — синтаксическая проверка каждого `<script>` (new Function) в собранном dist.

## Урок финального аудита v2 (2026-10-19, Ombra + Hale)
- **CSS-3D слои (preserve-3d, 7 картинок) рядом с непрерывной WebGL-анимацией** уронили Lighthouse desktop с 99 до 59 (TBT 21 с), даже вне экрана. Решение: такие блоки существуют только у вьюпорта — IntersectionObserver (rootMargin 300px) + `display:none` вдали. Всегда сравнивать Lighthouse с предыдущей версией (git show старого коммита → build → lighthouse) — так регрессия ловится за минуту.
- Мелкие подписи акцентным цветом проверять на 4.5:1 (Hale: #93654A → #8A5D43).
- Тап-цели ≥24 px (WCAG 2.2): текстовые ссылки в меню/подвале — `display:inline-block; padding-block`.
- Пульсирующая «живая» точка без живых данных — шаблон, убирать.
- Мобильный LCP Ombra 5 с — цена утверждённого кинематографичного интро (буквы + фильм), не регрессия.
